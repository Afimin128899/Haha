# Telegram Session Bot

Один Python 3.12 сервис: aiogram 3, Telethon, SQLite и постоянный Railway Volume. Только личные чаты и разрешённые ID. Реальные аккаунты при разработке не подключаются.

## Запуск на Railway

1. Создайте бота через BotFather и получите свои API_ID/API_HASH на my.telegram.org. Не помещайте их в Git.
2. Создайте Railway Service из этого репозитория. Dockerfile устанавливает зависимости; команда запуска задана в railway.toml.
3. Добавьте **Volume**, смонтируйте в `/data`. Укажите `DATA_DIR=/data`. Без Volume очередь, сессии и архивы не переживут новый deploy.
4. В Railway Variables задайте `BOT_TOKEN`, `API_ID`, `API_HASH`, `ALLOWED_IDS` (числовые Telegram ID через запятую). Дополнительные настройки приведены в `.env.example`. Пример не содержит рабочих секретов. `.env` автоматически не загружается.
5. Оставьте **одну replica**, без второго сервиса и второго polling-процесса. Публичный HTTP-порт и домен не нужны. Отключите webhook токена до запуска polling.
6. После deploy проверьте `/version`, `/settings`, загрузку тестовой сессии, затем `/status` и `/archives`. Railway автоматически предоставляет `RAILWAY_GIT_COMMIT_SHA` при Git deploy; при других источниках задайте его самостоятельно.

SQLite использует WAL и synchronous=FULL. Volume должен поддерживать POSIX SQLite и локальные файловые блокировки. Не подключайте одну SQLite-базу через сетевую файловую систему к нескольким серверам. `polling.lock` защищает только процессы с доступом к одному диску; копию на другом сервере он не обнаруживает. TelegramConflictError останавливает polling и выводит объяснение в журнал. Конфликт webhook также нужно устранить вручную.

## Использование

`/start`, `/help`, `/status`, `/pause`, `/resume`, `/cancel [ID]`, `/archives`, `/settings`, `/version`. `/input ID значение` — ответ конкретной задаче. Бот по возможности удаляет сообщение с кодом/паролем; удаление не гарантирует исчезновение копий на устройствах и серверах Telegram. Используйте приватный сервис и доверенный сервер.

Загрузите `.session` или ZIP, содержащий пары `имя.session` и `имя.json` **в корне**. Папки, повторные имена, ссылки, пути с `..`, абсолютные пути и другие файлы отклоняются. Лимит относится и к сжатому файлу, и к суммарному объёму распаковки; максимум 100 элементов ZIP. Telegram Bot API в облаке обычно ограничивает скачивание 20 МБ, поэтому стандартный лимит 20 МБ не следует повышать без проверки API.

Ожидается SQLite-сессия Telethon с 256-байтным auth_key. StringSession, tdata и зашифрованные архивы не поддерживаются. JSON может содержать `device_model`, `system_version`, `app_version`, `lang_code`, `system_lang_code`, `proxy` и пароль в `password`, `twoFA` или `two_fa`. API-ключи из JSON намеренно игнорируются: используются только переменные окружения. Proxy имеет формат `{"proxy_type":"socks5","addr":"127.0.0.1","port":1080,"username":"...","password":"...","rdns":true}`. Прокси применяются к Telethon, не к Bot API. Не загружайте недоверенные SQLite-файлы: библиотека SQLite должна своевременно обновляться.

Для каждой пары выбирается режим:

- Проверка авторизации: без запроса кода, нового входа, очистки и завершения других сеансов.
- @SpamBot: отправка `/start` официальному боту и передача его фактического ответа пользователю. Текст ответа не интерпретируется как гарантия отсутствия ограничений.
- Завершение других сеансов: отдельное подтверждение, `auth.resetAuthorizations`, текущая загруженная авторизация сохраняется. Telegram может запретить действие для слишком новой авторизации.
- Очистка: пользователь может отдельно выбрать **удаление всех контактов** или **всех облачных черновиков сообщений**. Перед действием бот показывает полный список действий и требует подтверждение. Удаление отправленных сообщений, диалогов, фото и иных данных не реализовано.
- Миграция: новая независимая авторизация с временной копией источника. Старую авторизацию бот **не завершает**, даже после успешной миграции. Завершение других сеансов — отдельный режим, который можно запустить с полученной новой сессией.

## Миграция

До запроса кода бот проверяет исходную авторизацию, разрешает `777000` и телефон `+42777` в реальные сущности Telegram, исключает дубликаты ID и сохраняет последнюю границу сообщений каждого чата отдельно. Доступность `+42777` зависит от аккаунта; невозможность разрешить телефон показывается отдельно. Только при `SentCodeTypeApp` бот ищет новые входящие сообщения с ID выше соответствующей границы. Время сообщений не используется. Отсутствие сообщения, недоступность чатов и ошибка распознавания различаются.

Автоматическое ожидание — 45 секунд, затем ручной ввод в течение 10 минут. SMS/звонок требуют ручного ввода, email/Fragment/другие нестандартные способы завершаются понятным статусом с сохранением источника. `SentCodeSuccess` обрабатывается отдельно. Повтор запрашивается пользователем словом `resend`: только при `next_type` и `timeout`, после ожидания timeout, максимум один раз. FloodWait не обходится и не повторяется автоматически. Срок ожидания сохраняется в SQLite для известного аккаунта; следующие задачи этого аккаунта ждут окончания срока, в том числе после рестарта. При необходимости запрашивается 2FA; пароль из JSON можно исправить вручную.

Telegram определяет доставку кода. Бот не гарантирует доставку и не переключает её в обход решения Telegram. Неправильный/просроченный код завершает задачу без автоматических попыток. Telegram иногда аннулирует код, пересланный в чат: это нужно проверить на своём аккаунте. Для сложных подтверждений используйте официальный клиент.

После подтверждения новой авторизации клиент отключается, SQLite-сессия закрывается, ZIP записывается во временный файл на Volume, выполняются fsync файла и каталога и атомарное переименование. Только затем результат отмечается готовым и отправляется. Выдача каждого результата независима от остальных задач. Ошибка отправки не удаляет архив: `/archives` выдаёт только результаты владельца. JSON результата содержит только несекретные параметры устройства; proxy и 2FA не экспортируются. Для подключения результата нужны API_ID/API_HASH из окружения.

## Очередь и хранение

Очередь постоянная, с настраиваемой параллельностью. Одинаковые auth_key блокируются до подключения, затем перед изменениями используется реальный Telegram user ID, чтобы разные сессии одного аккаунта не выполняли операции одновременно. При восстановлении ожидающие задачи продолжаются, завершённые не повторяются. Выполнявшиеся при аварии помечаются `interrupted` и автоматически **не повторяются**: Telegram мог уже выполнить необратимый запрос. Создайте новую задачу после проверки состояния аккаунта. Ручные вводы не переживают перезапуск и привязаны к конкретной задаче.

Пауза останавливает запуск ожидающих задач своего пользователя. Уже запущенные продолжаются. Отмена прекращает ожидание и закрывает клиентов, удаляет рабочие копии, но не откатывает уже принятый Telegram запрос. Черновики с выбором режима сохраняются, старые inline-кнопки работают до истечения срока хранения.

Оригиналы и результаты сохраняются по умолчанию 7 дней с создания задачи. Периодически удаляются файлы завершённых/ошибочных/отменённых/прерванных задач и черновиков; секретный config очищается. Активные и ожидающие задачи не удаляются по сроку. На старте удаляются временные рабочие копии, staging, незавершённые ZIP и исходные файлы, не привязанные ни к одной задаче. Очередь хранит техническую историю (ID владельца, отпечаток аккаунта, этап). Секреты на Volume не зашифрованы приложением: ограничьте доступ к Railway и резервным копиям. Удаление файла не гарантирует физическое стирание блоков SSD или backup. Исходный файл не уничтожается при ошибке до штатного истечения срока хранения.

Номера телефонов в интерфейс и журнал не выводятся. Коды, 2FA, auth_key, phone_code_hash и тексты служебных сообщений не записываются в логи. Ответ @SpamBot передаётся только владельцу. Нельзя включать отладочное логирование Telethon или логирование входящих update с `/input`. Бот не создаёт новые логины при обычной проверке, но Telethon может обновить служебные поля SQLite-копии.

## Разработка и CI

```sh
python3.12 -m venv .venv
. .venv/bin/activate
pip install -e '.[test]'
pytest -q
python -m sessionbot
```

Перед запуском экспортируйте переменные окружения; локально задайте `DATA_DIR` на записываемый каталог. CI выполняет офлайн-тесты на Python 3.12. Тесты используют поддельные клиенты и не требуют токена или реальных сессий.

Перед эксплуатацией отдельно проверьте на своём аккаунте: реальную авторизацию/отзыв, доступность обоих служебных источников, фактические способы доставки, 2FA, @SpamBot, прокси, ограничения на resetAuthorizations, корректность сохранённой сессии после рестарта Railway и повторную выдачу архива. Удаление контактов проверяйте только на аккаунте с тестовыми контактами после осознанного подтверждения. Успех моков не означает полную проверку Telegram-интеграции.
